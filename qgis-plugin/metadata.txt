description=dsh-qgis-driver: a remote-control and AI-assistant plugin for QGIS. Exposes QGIS internals via a token-authenticated REST API (/api/*) and file JSONL channels to local or remote AI clients; includes a built-in AI assistant panel for OpenAI-compatible APIs and a hot-reload watcher for plugin development
about=Exposes QGIS internals to clients via commands.jsonl/results.jsonl and REST /api/*. By default the HTTP server binds 127.0.0.1; set QGIS_LIVE_HOST (e.g. 0.0.0.0) and QGIS_LIVE_PORT to expose it to a remote machine, and QGIS_LIVE_API_KEY to set a stable Key for remote clients. All channels require a per-session token (and the API key when set) stored in user-only files. Disabled by default; enable via the Plugins > dsh-qgis-driver menu or WEBENGINE_LIVE_DIR env. The Connection Info dialog (menu; auto-opens on first enable) shows the REST endpoint, token and paste-ready client configs. pyeval executes arbitrary Python inside QGIS — the trust boundary is the local user account. The AI Assistant dock (Plugins > dsh-qgis-driver > AI Assistant) connects an OpenAI-compatible, Gemini or GitHub Copilot API and lets the model run the driver's tools via function calling. The Hot Reload submenu (Plugins > dsh-qgis-driver > Hot Reload) reloads a chosen plugin in-place (sys.modules cleanup + reloadPlugin + dialog reopen) for development without restarting QGIS. The Deploy Mode dialog (Plugins > dsh-qgis-driver > Deploy Mode) switches the deploy mode between development (junction = repository sources) and usage (restored parked copy) via the harness deploy script. The shared GeoSuite toolbar hosts all managed-plugin toolbar items; the driver adds an always-visible mode badge (Development/Usage) at its head — click it to open the Deploy Mode dialog.
